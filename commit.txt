The dataset package builds itself, and importing it no longer destroys it

generators.py is written by five generator scripts, and those scripts did their work
at import time. The package imports generators.py when it loads, so importing part
one truncated the file that everything else needs, and any sweep that touched the
scripts in order left the package broken behind it. They refuse import now and write
only when run directly.

The file they had left behind carried every orchestration function six times and one
layer generator six times, from having been appended to repeatedly. Rebuilt: one of
each.

The generated header never imported the three chain functions its own generators
call on every dataset, so every generate() died on the closure verdict it stamps.
The header imports them, and the fix is in the generator rather than in its output.

Four organism designs called for an actionable package that was never generated. It
exists now, in the generator: the design package plus a coding genome, protein
backbones, a plasmid and a metabolic model, with anything the tree cannot supply
recorded as unavailable rather than dropped. Human, gills, photosynthetic and treople
all run.
