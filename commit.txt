Verification was overwriting the file it verified

Three faults in one command. The identity phase takes source text and was handed a
file path, so it parsed the path itself as Python and failed on line one, and the
whole verification reported a syntax error against a file that was fine. CLINK writes
what it is given to the path it is given, and it was given the source path, so
running verify rewrote the source it had just checked and prepended a shebang to it.
And CLINK returns nothing, so it was reported as failed regardless.

Source text now flows to the operators that want it, CLINK runs against a temporary
file and is judged by what it wrote, and the file being verified is left untouched.
The verification passes, split to fuse, semantic identity confirmed.
