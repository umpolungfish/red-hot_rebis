The patch scripts were corrupting the file they patch, every time anything imported them

Six scripts rewrite the retrosynthetic pipeline, and they did it at import time, so
every sweep of this repository reapplied them. Three separate faults compounded.

The first inserted its import by scanning for the end of a parenthesised import
statement and stopping at the first continuation line, which put the new import
inside the brackets. It finds the closing bracket now.

Two of them inserted a multi-line block by looping over its lines and inserting each
at the same index, which writes the block backwards. That is where the methods with
their bodies in reverse came from, and why the file kept returning to that state
after I repaired it: I was repairing the output while the cause reapplied itself.
Blocks go in as blocks.

None of them checked whether their own result was already in place, so each run
duplicated everything it had inserted before. Three rounds grew the file by three
hundred lines and broke it at runtime. Each now finds its own result and stops, and
three rounds leave the file byte for byte the same.

They also refuse to be imported, since running is the only time a patch should write.

The pipeline runs.
