Two more of the same bug, found by tracing every file that actually crosses from a canonical mark source into a local table, not by re-grepping the glyph.

rhr_p4rky/ligand_from_active_site.py's _MARK_TO_SHORT keyed Winding/Protection as "◻", but AA_TO_PRIMITIVE builds itself straight from vox_bridge.AA_MARK, which carries the real "⊡" from Vox's own genetic_table.AA_GLYPH — this was the crash on rebis.ligand --help, since AA_TO_PRIMITIVE is built at import time.

rhr_p4rky/ligand_from_site_pdb.py's _FULL_TO_SHORT had the identical wrong key, but nothing there indexes by it directly — it's inverted into _SHORT_TO_FULL and read back with .get(p_short, p_short), so the miss never raised. It silently returned "◻" for the Winding/Protection slot, which then failed to find that field in a real sidechain_algebra tensor tuple (correctly keyed "⊡") and fell through to a bare "W" that also isn't a key there — so every real PDB-driven ligand design was computing its Winding/Protection ordinal from zero residues instead of the real weighted average, with nothing to say so.

Both are the same one-character fix as sidechain_algebra.py: "◻" to "⊡" in the one dict each file actually indexes canonical marks with. Checked against real data, not just import: all 80 sidechain-times-environment pairs, a live-fetched 239-residue PDB through rebis.sidechain, and a full rebis.ligand --pdb 1LYZ --auto-active run producing real SMILES candidates with all twelve primitives populated, Winding/Protection included.

Traced every other file using "◻" against the actual import graph (vox_bridge, genetic_table, crystal_navigator, sidechain_algebra) rather than assuming: ch3mpiler_serpentrod_pipeline.py, genetic_code.py, gene_imscriber/tuples.py, and serpentrod/stratified_predictor.py all import canonical marks too, but only ever pass them through or format them — none of them index a local "◻"-keyed table by one, so none of them share this bug. Every other file using "◻" (dozens, across clink/, materials/, alchemical_bridge/, ch3mpiler/, plasma/, gene_to_protein_pipeline.py, genetic_tuples.py, serpent_rod_v2.py, dual_link_sicpovm.py, and more) never imports a canonical-mark source at all — "◻" there is that file's own self-consistent internal convention, untouched, not this bug.
