Undoing damage I did in the previous commit

Two faults, both mine, both from committing a working tree I had not read.

The retrosynthetic pipeline was left unparseable. My previous commit inserted
duplicated lines into it and wrote one function's body in reverse order, and I
committed it without checking that the file still parses. Restored to the revision
before that commit, where it parses.

And running the tools rewrote their own recorded results, which a blanket add then
swept into the commit. The alloy simulation's stored result went from a million lines
to a couple of hundred because my run replaced it. Every results file is restored to
what was recorded. Running a tool is not a reason to overwrite the run that was kept.

The printing helpers took no end and one of them called itself instead of printing,
so any caller reaching the unstyled branch recursed until it died. They take an end
now, and print-style trailing values, which is how their callers were already using
them.

mark, and got a dict where it wanted a number.
